# 製作・使用ガイド

このダンパーを自分でも作ってみたい人向けの手順書です。
**AIエージェント（Claude Code など）がなくても最後まで到達できるように**、
実際に踏んだ手順と落とし穴をそのまま書いています。

---

## 0. 最初に読んでほしいこと

正直に書きます。**このプロジェクトは「安く手軽にROMを吸い出す」用途には向きません。**

- 62pinカードエッジコネクタの実装が物理的にかなり厳しい（後述）
- 完成後も読み出しが一発で決まらず、検証と再読み出しの仕組みが要る
- 1カートの吸い出しに30分〜数時間かかる

目的が「手持ちの部品だけで動くものを作る」「仕組みを理解する」ならとても面白い題材です。
実用性が目的なら、[Sanni's Open Source Cart Reader](https://github.com/sanni/cartreader) か
市販品を強くおすすめします。

---

## 1. 用意するもの

| 品目 | 数 | 備考 |
|---|---|---|
| Arduino Nano（互換品可） | 3 | クローン品は書き込み時に Old Bootloader 指定が必要なことが多い |
| SFC 62pin カードエッジコネクタ | 1 | ジャンクのスーパーファミコン本体から取り外すのが安上がり |
| ユニバーサル基板 | 1 | 2.54mmピッチ。コネクタとの寸法差は後述の力技で吸収する |
| 配線材 | — | Nano↔カートリッジはUEW（ポリウレタン銅線）が取り回しやすい。他はAWG22程度 |
| 積層セラミックコンデンサ 0.1µF | 数個 | 各Nanoとカートの電源ピン直近に。**あった方がよい** |
| 電解コンデンサ 10〜47µF | 1 | 電源引き込み部に |
| SH1106 or SSD1306 OLED (I2C) | 0〜1 | 進捗表示用。無くても動く |
| 3Dプリント部品 `支柱.stl` | 4 | 基板の底面を机から浮かせる脚。裏面配線を潰さないために必要 |

PC側は Python 3 と `pyserial` だけです。

```bash
pip install pyserial
```

## 2. コネクタの取り付け（最大の難所）

### 寸法が合わない

SFCのカードエッジコネクタは**ピッチ2.50mm**で、ユニバーサル基板の2.54mmと合いません。
さらに**列間隔とキー溝の位置も非標準**です。31ピン分でおよそ1.2mmずれます。

実際にやった対処:

1. **キー溝（切り欠き）を超音波カッターで切断する。** 誤挿入防止のためだけの構造なので、
   電気的には切っても問題ありません
2. 上からかぶせる金属シールドで位置決めして押し込む
3. 結束バンドで固定する

### 切った後に必ず確認すること

- **隣接ピン間が短絡していないか。** 切りくずの金属粉が端子間に挟まると、
  1ピンずつの導通チェックでは気づけません。**隣り合うピン同士**に抵抗計を当てて
  無限大（非導通）を確認してください
- **金属シールドが信号ピンに触れていないか。** シールドがGNDに落ちるのは構いませんが、
  信号ピンに触れるとその線がGNDに固定されます
- 挿抜を数回繰り返して、毎回同じ導通結果が出るか（接触の再現性）

### 3Dプリント部品

`支柱.stl` を**4本印刷**し、基板の四隅に取り付けて底面を机から浮かせてください。
裏面は配線がびっしり出ているので、直置きすると断線やショートの原因になります。

## 3. 配線

62pinのうち、実際に配線が必要なのは以下だけです。GND/VCCは重複ピンが多いので全部つなぐ必要はありません。

### カートリッジ側ピン番号順

| カートピン | 信号 | 接続先 |
|---|---|---|
| 5, 36 | GND | 共通GNDレール（両方つなぐのが望ましい） |
| 27, 58 | +5V | 共通+5Vレール |
| 6〜17 | A11〜A0 | Nano-1 D13〜D2（番号が逆順なので注意） |
| 37〜40 | A12〜A15 | Nano-1 A0〜A3 |
| 41〜48 | A16〜A23 | Nano-3 D2〜D9 |
| 19〜22 | D0〜D3 | Nano-2 A0〜A3 |
| 50〜53 | D4〜D7 | Nano-2 A4, A5, D8, D9 |
| 23 | /RD | Nano-2 D2 |
| 49 | /ROMSEL | Nano-2 D3 |
| 54 | /WR | **+5Vへ直結**（読み出し専用のため） |
| 26 | /RESET | **+5Vへ直結** |

未接続でよいピン: 1(SYSCLK), 2/33(拡張), 3/4/28〜30/34/59〜61(周辺アドレスバス・/PRD),
18(/IRQ), 24/25/55/56(CIC), 31/62(オーディオ), 32/35(WRAM制御), 57(PHI2)

**CICロックアウトチップは一切関係ありません。** ROMを直接バス読みするだけなので認証は絡みません。

### Nano間

| 信号 | 接続 |
|---|---|
| ADDR_RESET | Nano-2 D10 → Nano-1 A5 |
| ADDR_STROBE | Nano-2 D4 → Nano-1 A4 |
| BANK_RESET | Nano-2 D5 → Nano-3 D10 |
| BANK_STROBE | Nano-2 D6 → Nano-3 D11 |
| GND | 3台すべて共通に |

OLEDを付ける場合は Nano-2 の D11(SDA) / D12(SCL) へ。
ハードウェアI2Cピン(A4/A5)はカートのデータバスで埋まっているので、ソフトウェアI2Cを使います。

### 電源について

3台のNano + OLED + カートで実測おおむね100〜150mAです。USBケーブル1本のバスパワーで
動きますが、**長時間の連続動作では電圧降下が起きて読み出しが化けます**（後述）。
DCジャック＋降圧モジュールで外部給電できるようにしておくと安心です。

## 4. ファームウェアの書き込み

3台それぞれに対応するスケッチを書き込みます。

| ボード | スケッチ |
|---|---|
| Nano-1 | `nano1_addr_low/` |
| Nano-2 | `nano2_master/` |
| Nano-3 | `nano3_bank/` |

Arduino IDE でも `arduino-cli` でも構いません。CLIなら:

```bash
arduino-cli compile --fqbn arduino:avr:nano:cpu=atmega328old nano1_addr_low
arduino-cli upload -p COM3 --fqbn arduino:avr:nano:cpu=atmega328old nano1_addr_low
```

### よくあるエラー

```
avrdude: stk500_recv(): programmer is not responding
```

クローンNanoでは **`cpu=atmega328old`（Old Bootloader）** を指定しないと書き込めません。
Arduino IDE の場合は「ツール → プロセッサ → ATmega328P (Old Bootloader)」です。

それでも失敗する場合は、USBケーブルを一度抜き差ししてください。実際これで直ったことが何度もあります。

## 5. 吸い出し

### GUIを使う場合（推奨）

```bash
python gui/sfc_dumper_gui.py
```

1. シリアルポートを選ぶ
2. 「カートを判定」でROMサイズとマッピング(LoROM/HiROM)を自動認識
   - タイトル名でデータベース検索して正確なバイト数を引くこともできます
3. `nano2_master.ino` の設定を判定結果に合わせて書き込み直す
4. 「ダンプ開始」

### CLIを使う場合（確実）

**バンク単位方式を使ってください。** 長時間連続で読むと化けるためです。

```bash
python host/dump_by_bank.py --port COM3 --banks 32 --mapping hirom --out MyGame.sfc
```

1バンク（64KB）ごとにNanoをリセットして読み直し、**2回読んで完全一致するまで繰り返します**。
確定したバンクは `MyGame.sfc.banks/` にキャッシュされるので、中断しても続きから再開できます。

## 6. 検証（ここが一番大事）

**ヘッダのチェックサム欄だけを見て「読めた」と判断しないでください。**

内部ヘッダにはチェックサムとその補数が入っており、この2つのXORが `0xFFFF` になるかを
見るチェックがあります。しかしこれは**ヘッダの4バイトが正しく読めているかを見ているだけ**で、
ROM本体が壊れていても通ってしまいます。実際これで「成功した」と誤判定しました。

正しい検証は**ROM全体のバイト総和**です。

```python
# HiROMなら 0xFFC0、LoROMなら 0x7FC0 がヘッダ位置
off = 0xFFC0
checksum = rom[off+30] | (rom[off+31] << 8)   # ヘッダが主張する値
computed = sum(rom) & 0xFFFF                  # 実際に計算した値
print(computed == checksum)
```

さらに確実なのは、エミュレータに読ませることです。**Snes9x / RetroArch の Snes9x コアは
ログに `Checksum OK` / `Invalid Checksum` を出力します。**

```bash
retroarch -L cores/snes9x_libretro.dll MyGame.sfc -v --log-file=log.txt
```

No-Intro のCRC32と照合するのも有効です。RetroArch同梱の
`database/rdb/Nintendo - Super Nintendo Entertainment System.rdb` にCRCが入っており、
本リポジトリの `gui/rdb.py` で読めます（ネットワーク不要）。

## 7. トラブルシューティング

### 全部 0x00 になる

カートが挿さっていない、GNDが共通化されていない、`/RESET` が+5Vに繋がっていない、
`/RD` や `/ROMSEL` の配線間違い、のいずれかです。まずカートが挿さっているか確認を（実話）。

### 同じ値が2回ずつ並ぶ

アドレスの最下位ビット(A0)が固定されています。カートpin17 ↔ Nano-1 D2 の配線を確認してください。

### 32KB周期で内容が繰り返す

**これは故障ではありません。** LoROMではバンク内の上位32KBと下位32KBが同じ内容に
ミラーされます（A15がROM選択に関与しないため）。ダンプ後に前半32KBだけ抽出してください。
HiROMなら64KBフルに使うのでミラーは出ません。

### 毎回違う位置で少しずつ化ける

長時間の連続読み出しが原因の可能性が高いです。**バンク単位方式**に切り替えてください。
1バンクだけ単独で読む分には、実測で完全に再現します（2回読んで差分0バイト）。

原因は数分間の連続動作による電圧降下と見ています（USBポートのポリスイッチ発熱が有力）。
外部給電にできるなら試す価値があります。

### タイミングを長くしても直らない

読み出しの待ち時間は現行の100usで既に十分です。実測:

| 設定 | 同じバンクを2回読んだ差分 |
|---|---|
| RD=20us / ADDR=20us | 2 バイト |
| RD=100us / ADDR=100us | **0 バイト** |
| RD=400us / ADDR=400us | **0 バイト** |
| RD=1000us / ADDR=1000us | **0 バイト** |

待ちを伸ばしても改善しないので、タイミング以外を疑ってください。

### 読めないカートがある

Super FX / SA-1 / DSP-1 / S-DD1 / SPC7110 / CX4 などの**コプロセッサ搭載カートは
この設計では読めません**。ROMがコプロチップの内部バスにぶら下がっており、
カートのエッジコネクタから直接見えないためです。

該当タイトル例: スターフォックス、ヨッシーアイランド、スーパーマリオRPG、
星のカービィ スーパーデラックス、スーパーマリオカート、スターオーシャン など

## 9. 法的な注意

自分が正規に所有するカートリッジのバックアップを想定しています。
吸い出したROMデータの配布は著作権侵害にあたります。本リポジトリにもROMは含めていません。
