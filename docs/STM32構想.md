# STM32F103 + 74HCT による1チップ化の検討

**状態: 机上検討。まだ何も作っていない。**

現行機はNano 3枚でGPIOの不足を人海戦術で埋めている。1枚のマイコンで
まかなえるなら、USB変換チップ由来の 100 KB/s の壁も同時に消える。
ここでは「秋月・千石・共立・アリエクで買えるもの」に限って構成を検討する。

---

## 1. なぜ直結できないのか

STM32F103C8T6（Blue Pill）のGPIOは37本。必要な信号を数えると足りない。

| 信号 | 本数 |
|---|---|
| A0-A23 | 24 |
| D0-D7 | 8 |
| /RD, /ROMSEL, /WR | 3 |
| /RESET | 1 |
| CIC 4線 | 4 |
| マスタークロック(カート1番) | 1 |
| **合計** | **41** |

**41 > 37。落ちる。** さらにBlue Pillの実装では USB(PA11/PA12)、
SWD(PA13/PA14)、32.768kHz水晶(PC14/PC15) が埋まるので実際はもっと厳しい。

## 2. 本当の制約は5Vトレラントピンの数

**F103は全ピンが5Vトレラントではない。** アナログ入力を持つピンは非トレラント。

```
非トレラント : PA0-PA7, PB0, PB1, PC13, PC14, PC15
トレラント   : PA8-PA15, PB2-PB15          （計22本）
  うち USB で PA11/PA12、SWD で PA13/PA14 が埋まる → 実質18本
```

ただし**トレラントが要るのは入力方向だけ**である。

| 方向 | 対象 | 対策 |
|---|---|---|
| カート → MCU | D0-D7、CICのKey応答 | 5Vトレラントピンに直結（10本） |
| MCU → カート | アドレス・制御・クロック | 74HCTでシフト（トレラント不要） |

必要な10本に対して18本。**足りる。** 非トレラントのPA0-PA7は
出力専用として使えば無駄にならない。

## 3. 74HCTでなければならない理由

```
74HC  : V_IH = 3.5V (5V動作時) → 3.3V出力では規格を満たさない
74HCT : V_IH = 2.0V            → 3.3V出力でOK
```

**HCとHCTを間違えると動いたり動かなかったりする。** 買うときに必ず確認する。

---

## 4. ピン割り当て

### 出力専用（非トレラントピンを充てる）

| STM32 | 信号 | 行き先 |
|---|---|---|
| PA0-PA7 | LD0-LD7 | 573×4 の D入力へ共通バス |
| PB0 | LE_A | 573#1 ラッチ許可 (A0-A7) |
| PB1 | LE_B | 573#2 ラッチ許可 (A8-A15) |
| PC13 | /OE | 573×4 共通。10kΩで3.3Vへプルアップ |

`PC13` は駆動能力が3mAしかないが、HCTの入力はほぼ電流を食わないので問題ない。
**プルアップ先は3.3Vにすること。PC13は5Vトレラントではない。**

### 5Vトレラントピン

| STM32 | 信号 | 経路 |
|---|---|---|
| PB8-PB15 | D0-D7 | **カートに直結**（入力） |
| PB2 | LE_C | 573#3 ラッチ許可 (A16-A23) |
| PA8 | MCLK | 573#4 経由 → カート1番 |
| PA9 | /RD | 573#4 経由 |
| PA10 | /ROMSEL | 573#4 経由 |
| PB7 | /WR | 573#4 経由 |
| PB6 | /RESET | 573#4 経由 |
| PB5 | CIC_CLK | 573#4 経由 |
| PB4 | CIC_RESET | 573#4 経由 |
| PB3 | CIC_D0 | **直結**（オープンドレイン）+ 4.7kΩ→5V |
| PA15 | CIC_D1 | **直結**（オープンドレイン）+ 4.7kΩ→5V |

### 予約・使用不可

| ピン | 理由 |
|---|---|
| PA11, PA12 | USB D-/D+ |
| PA13, PA14 | SWD（書き込み・デバッグ） |
| PC14, PC15 | 32.768kHz水晶。外せば空くが用途なし |

**使用 29本 + USB 2 + SWD 2 = 33本。実質的な余りはゼロ。**

## 5. 設計上の注意

### PB8-PB15にD0-D7を置いた理由
`GPIOB->IDR >> 8` の1命令で8ビットまとめて読める。ここを飛び飛びに割ると、
読むたびにビットを組み立て直すことになって速度が出ない。

### PB3, PB4, PA15 を使うにはJTAG無効化が要る
これらはJTAGピンなので、起動時に一度だけ解放する。SWDは残るので書き込みはできる。

```c
__HAL_RCC_AFIO_CLK_ENABLE();
__HAL_AFIO_REMAP_SWJ_NOJTAG();   // JTAGだけ切る。SWDは残す
```

**これを忘れるとPB3/PB4/PA15が動かない。** 配線を疑う前にここを見る。

### PB2 は BOOT1 なので、リセット時にLowでなければならない
LE_C に割り当てたのは、573のLEが**Lowでラッチ保持**だから。リセット時にLow＝
アドレスが保持されたまま、で都合がよい。ここに「リセット時にHighであってほしい信号」
を置いてはいけない。

### /OE を必ず入れる
MCUのリセット直後、GPIOは入力（ハイインピーダンス）になる。/OEが無いと
573の出力が不定のままカートのアドレス線を叩く。10kΩのプルアップで
**電源投入時は出力禁止**にしておき、ファームが準備できてからLowに落とす。

### CICの2本はオープンドレインで済む
半二重で、双方が交互に喋る。STM32側をオープンドレイン出力にして5Vへプルアップすれば、
Lowは自分で引き、Highはプルアップが5Vまで持ち上げる。**シフタが要らない。**
ピンは5Vトレラントなので、相手が5Vを出しても壊れない。

### CICのカート側ピン番号は現物で確認すること
この表は機能名で書いてある。24/25/55/56 の対応は現行のNano-3の配線を正とする。

4個目は「ラッチ」ではなく単なるレベルシフタとして使う。74HCT541でもよいが、

## 7. 分かっている限界

**OLEDもSDカードも載らない。** 実質的な余りピンがゼロなので、
現行機のOLED表示を移植する余地がない。

必要なら **STM32F103RCT6（LQFP64、GPIO 51本）** の最小基板に上げる。
アリエクで千円前後。ピンが14本増えるので、OLEDのI2C 2本もSDのSPI 4本も入る。
Flashも256KB、RAMも48KBに増えるので、**バンクを丸ごとRAMに溜めてから
まとめて送る**ことができるようになる。速度面ではこちらの方が有利かもしれない。

## 8. 未検証の前提

以下は**まだ確かめていない**。作る前に潰すこと。

1. **カートの入力が74HCTの出力High(約4.8V)で確実に認識されるか。**
   ほぼ問題ないはずだが、実測していない。
2. **CICのオープンドレイン化が実際のCICと噛み合うか。**
   SuperCICの実装はプッシュプルで送って受信時にHi-Zにしている。
   オープンドレインでも論理的には成立するが、実物で確認していない。
3. **アリエクのBlue Pillに載っているのが本物のSTM32か。**
   CS32/CKSなどのクローンが混ざる。動くことが多いがUSBが不安定な個体がある。
4. **USBネイティブにして実際に何 KB/s 出るか。**
   理屈の上ではNanoの100 KB/sの壁は消えるが、
   ボトルネックがバスのタイミングに移るだけかもしれない。

# 付録: Raspberry Pi Pico (RP2040) の場合

**状態: 机上検討。**

秋月で買えるという一点でSTM32より条件が良い。ただし**5Vトレラントではない**ので、
レベル変換が両方向に必要になる。

## 1. 決定的な違い

```
STM32F103 : 入力は5Vトレラント → 変換は 出力側だけ
RP2040    : トレラント無し     → 変換は 両方向
```

RP2040のGPIOは絶対最大定格が 3.3V + 0.3V。**カートの5Vを直結すると壊れる。**
pakutoma氏の構成にレベル変換が入っているのはこのためで、避けようがない。

## 2. ピン数

Picoの外に出ているGPIOは26本（GP0-GP22, GP26-GP28）。
STM32の割り当てをそのまま持ってくると29本必要で、**3本足りない。**

そこで**ラッチ入力とデータバスを共用する**。8本浮いて21本になる。

共用が成立する理由は、両者が同時に使われないからである。

```
アドレス確定時 : /RD=High → カートはデータを出さない → MCUがバスを駆動して573にラッチ
データ読み出し : /RD=Low  → カートが駆動 → MCUは入力に切り替えて受ける
```

## 3. ピン割り当て

| GPIO | 信号 | 経路 |
|---|---|---|
| GP0-GP7 | SD0-SD7（共用バス） | 573×4のD入力 ／ LVC245経由でカートD0-D7 |
| GP8 | LE_A | 573#1 (A0-A7) |
| GP9 | LE_B | 573#2 (A8-A15) |
| GP10 | LE_C | 573#3 (A16-A23) |
| GP11 | /OE | 573共通。10kΩで3.3Vへプルアップ |
| GP12 | /RD | 573#4経由。**同時にLVC245の/OEへ** |
| GP13 | /ROMSEL | 573#4経由 |
| GP14 | /WR | 573#4経由 |
| GP15 | /RESET | 573#4経由 |
| GP16 | MCLK | 573#4経由 → カート1番 |
| GP17 | CIC_CLK | 573#4経由 |
| GP18 | CIC_RESET | 573#4経由 |
| GP19 | CIC_D0 | BSS138モジュール経由 |
| GP20 | CIC_D1 | BSS138モジュール経由 |
| GP26, GP27 | (空き) | I2C1。**OLEDが載る** |
| GP21, GP22, GP28 | (空き) | |

**使用21本 / 空き5本。** STM32構成と違ってOLEDが載る。

## 4. うまくいく仕掛け

### LVC245の/OEを/RDに繋ぐ
`74LVC245A` は VCC=3.3V で動かしても**入力が5Vトレラント**なので、
5V→3.3V の変換にそのまま使える。

その /OE を **/RD にそのまま繋ぐ**と、方向制御が自動になる。

```
/RD = Low  → 245が有効。カートのデータが3.3Vに落ちてMCUへ
/RD = High → 245がHi-Z。MCUが共用バスを駆動して573にラッチできる
```

**方向制御にGPIOを1本も使わない。** しかも論理的に間違えようがない。

### GP0-GP7を連番に置く
PIOのステートマシンが「/RDを下げる→待つ→8ビット読む→上げる」を
**CPUを介さずに**回せる。RP2040の速度の源はここにある。飛び飛びに割ると使えない。

### CICの2本はBSS138モジュールで済ませる
CICは半二重で双方が交互に喋る。これはI2Cと同じ使い方なので、
アリエクで100円前後の**BSS138 4chレベルシフタモジュール**がそのまま使える。
オープンドレイン+プルアップ方式なので、双方向の向き制御が要らない。

STM32ではここをピンのトレラント性で解決できたが、Picoではモジュールが1個要る。

## 5. 部品表

| 部品 | 個数 | 入手 |
|---|---|---|
| Raspberry Pi Pico | 1 | **秋月** |
| 74HCT573 | 4 | 3.3V→5V。**HCTであること** |
| 74LVC245A | 1 | 5V→3.3V。**VCC=3.3Vで使う** |
| BSS138 4ch双方向レベルシフタ | 1 | アリエク。CIC 2本用 |
| 62ピン カートスロット | 1 | 流用 |
| 0.1µF セラミック | 6 | 各IC直近 |
| 100µF 電解 | 1 | |
| 10kΩ | 1 | /OE プルアップ |

**ロジックIC 5個 + モジュール1個。** STM32より1個多い。
その代わり**ST-Linkが要らない**（USBにドラッグ&ドロップで書ける）。

## 6. STM32との比較

| | Pico | Blue Pill |
|---|---|---|
| 秋月で買えるか | **○** | ✗（アリエク） |
| 5Vトレラント | ✗ | ○（一部のみ） |
| レベル変換 | **両方向** | 出力側のみ |
| ロジックIC | 5個+モジュール | 4個 |
| GPIO | 26（21使用） | 37（29使用） |
| OLED | **載る** | 載らない |
| RAM | **264KB** | 20KB |
| PIO | **あり** | なし |
| 書き込み | **USB直** | ST-Link必要 |
| 速度の実績 | **200 KB/s（pakutoma氏実測）** | 不明 |

## 7. どちらを採るか

**部品点数だけならSTM32、それ以外はすべてPicoが有利。**

決め手になりそうなのは3つ。

1. **秋月で買える**（今回の制約そのもの）
2. **pakutoma氏が200 KB/sを実測している。** 机上の見積もりではない
3. **264KBのRAM。** 64KBのバンクを丸ごと溜めてから一気に送れる

ロジックICが1個増えることは、これらと引き換えにするなら安い。

## 8. 未検証の前提

1. **74LVC245Aの/OEを/RD(5V)に直結してよいか。**
   LVCは5Vトレラントなので問題ないはずだが、実測していない。
2. **BSS138モジュールがCICの速度に追いつくか。**
   プルアップで持ち上げる方式なので立ち上がりが鈍い。
   CICは1ビットあたり372パルスと遅いので大丈夫と見ているが、確認していない。
3. **共用バスの切り替えが実際のタイミングに間に合うか。**
   入出力の切り替えに時間がかかると、せっかくのPIOが台無しになる。

# 付録2: Waveshare Core2350B (RP2350B) の場合

**状態: 机上検討。実物の仕様はWaveshareの公表値による。**

## 1. 何が変わるか

RP2350**B** は RP2350A（Pico 2）と違って **GPIO が 48 本**ある。
これで**ラッチが不要になる**。

| | Pico (RP2040) | Core2350B (RP2350B) |
|---|---|---|
| GPIO | 26 | **48** |
| SRAM | 264 KB | **520 KB** |
| PSRAM | なし | **0 / 2 / 8 MB（選択可）** |
| Flash | 2 MB | 16 MB |
| PIOステートマシン | 8 | **12** |
| クロック | 133 MHz | 150 MHz |
| 5Vトレラント | ✗ | **✗（変わらず）** |

**5Vトレラントでないのは同じ**なので、レベル変換は両方向に必要なまま。
増えたのはピンとメモリである。

## 2. ラッチが要らなくなる

必要な信号は41本。**48本あるので全部直結できる。**

| GPIO | 信号 | 本数 |
|---|---|---|
| GP0-GP23 | A0-A23 | 24 |
| GP24-GP31 | D0-D7 | 8 |
| GP32 | /RD | 1 |
| GP33 | /ROMSEL | 1 |
| GP34 | /WR | 1 |
| GP35 | /RESET | 1 |
| GP36 | MCLK | 1 |
| GP37 | CIC_CLK | 1 |
| GP38 | CIC_RESET | 1 |
| GP39 | CIC_D0 | 1 |
| GP40 | CIC_D1 | 1 |
| GP41-GP47 | 空き | 7 |

**41本使用、7本空き。** OLEDのI2C 2本もSDのSPI 4本も入る。

読み出しサイクルが単純になる。

```
ラッチ方式 : 8bit書く→LE_A→8bit書く→LE_B→8bit書く→LE_C→/RD→読む   (7手)
直結方式   : 24bitまとめて書く→/RD→読む                            (3手)
```

**手数が半分以下。** これが速度に効く。

## 3. SA-1にとっての本命は PSRAM

8MB版を選ぶと、**4MBのROMを丸ごとRAMに落としてからPCに送れる。**

現行機はSA-1の窓の中で93秒間ずっとUSB転送を続けている。
PSRAM版なら、**窓の中でやるのはバス読み出しだけ**でよい。

```
現行機      : 窓の中で 93秒 必要（バス読み+USB転送が同時進行）
Core2350B   : 窓の中で 2〜4秒 必要（バス読みのみ。転送は窓が閉じた後）
```

バス側の理論値は、ROMのアクセス時間200ns + HCTの遅延13ns で
1サイクル300nsとすると 3.3 MB/s。4MBなら1.3秒。
余裕を見て1µs/byteでも4.2秒。

**窓の要求が93秒から数秒に落ちる。** 34連敗している今の問題に、
速度の話としてではなく**成功条件の話として**効く。

ただしこれは「窓の長さが有限で、短い方が有利」という仮説に立っている。
**その仮説自体はまだ検証されていない。**

## 4. 部品表

| 部品 | 個数 | 備考 |
|---|---|---|
| Waveshare Core2350B（**8MB PSRAM版**） | 1 | PSRAM版でないと3章の利点が出ない |
| 74HCT541（または245） | 4 | 出力31本を3.3V→5V |
| 74LVC245A | 1 | D0-D7 を5V→3.3V。VCC=3.3V |
| BSS138 4chレベルシフタ | 1 | CIC 2本 |
| 62ピン カートスロット | 1 | 流用 |
| 0.1µF | 7 | 各IC直近 |
| 100µF | 1 | |

**IC 5個 + モジュール1個。Picoと同数。**
ラッチが要らなくなった分がレベルシフタに置き換わっただけで、部品は減らない。

## 5. 実装上の注意

### E9エラッタ。**必ず A4 ステッピングを買うこと**
初期のRP2350には、入力ピンが約2.1Vで固着する不具合(E9)があった。
**バス読み出しでこれが起きると、データが化けたまま気づけない。**

- 2025年7月のA4ステッピングで修正済み
- 刻印が `RP2350B0A4` であることを確認する
- 2025年中頃以降の出荷分は該当するはずだが、**現物の刻印を見ること**

### PIOのGPIOウィンドウ
RP2350のPIOは一度に32本の窓しか見られない（GPIOBASEで 0-31 か 16-47 を選ぶ）。
A0-A23とD0-D7でちょうど GP0-31 を使い切るので、**制御線(GP32以降)が窓の外に出る。**

PIOブロックが3つあるので、
- PIO0 … base=0 でアドレス出力
- PIO1 … base=16 でデータ+制御

と分ければよい。**この分割が要ることを知らずに設計すると詰まる。**
（GPIOBASEがブロック単位かステートマシン単位かは、データシートで確認すること）

### USBがFPCコネクタ経由
Core2350Bは基板上にUSBポートを持たず、**6ピンのFPCコネクタ + 変換基板**で出す。
抜き差しの多い工具としては弱点になる。ケースを作るなら、
変換基板ごと固定してUSBコネクタだけを外に出す設計にする。

### 2.54mmの64ピン
キャリア基板に載せる前提の「コア基板」であって、Picoのように単体で
ブレッドボードに挿す用途は想定されていない。**ユニバーサル基板で試作するなら
先にピンヘッダを立てる必要がある。**

## 6. 入手性

Waveshare製なのでアリエクにはある。**秋月・千石・共立にあるかは未確認。**
PSRAM 8MB版は品番が分かれているので、注文時に取り違えないこと。

## 7. 3案の比較

| | Blue Pill | Pico | Core2350B |
|---|---|---|---|
| ロジックIC | 4 | 5+M | 5+M |
| ラッチ | 必要 | 必要 | **不要** |
| GPIO余り | 0 | 5 | **7** |
